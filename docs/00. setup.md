# Setup local

## Requisito real para esta version del proyecto

Para levantar y validar el stack de **Docker Compose** (Fases 0-5, 7-8) solo necesitas:

- Docker Desktop
- Docker Compose
- PowerShell

`k6` local o Python local no son necesarios (el seeder y k6 corren dentro de contenedores).

## Kubernetes (Fase 6+)

Para el cluster de Kubernetes (Fases 6-7, ya validadas en este repo) sí se necesitan
`kubectl` y `minikube`. En Windows con Docker Desktop:

```powershell
winget install -e --id Kubernetes.minikube
minikube start --driver=docker
minikube addons enable metrics-server   # requerido para que el HPA lea CPU%
```

`kubectl` ya viene incluido con Docker Desktop en Windows
(`C:\Program Files\Docker\Docker\resources\bin\kubectl.exe`).

Construir y cargar las imagenes de los 5 microservicios (coincide con
`imagePullPolicy: Never` en `k8s/base/deployment.yaml`):

```powershell
foreach ($svc in "user-service","inventory-service","payment-service","notification-service","order-service") {
  docker build -t "${svc}:latest" ".\services\$svc"
  minikube image load "${svc}:latest"
}
```

Aplicar los manifiestos:

```powershell
kubectl apply -f k8s/base/
kubectl apply -f k8s/resilience/hpa.yaml
```

`cli.py` puede apuntar al cluster (en vez de a Compose) via `kubectl
port-forward` + variables de entorno de puerto, sin cambios de código - ver
`docs/TOOLING.md`. Detalle completo del despliegue, HPA y MTTR en
`docs/tests/kubernetes-results.md`.

Helm no se usó en este repo pese a estar mencionado en la propuesta
académica original - los manifiestos de `k8s/` son YAML plano.

## Comandos base

```powershell
docker --version
docker compose version
docker info
```

## Arranque

```powershell
docker compose down -v
docker compose up --build -d
docker compose ps
```

## Si BuildKit falla

```powershell
docker compose build --no-cache
docker compose up -d
```
